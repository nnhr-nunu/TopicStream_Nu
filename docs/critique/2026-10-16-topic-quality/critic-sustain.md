## 1. 総合点と観点の点

- **総合点: 3**（芯はあるが、広める前に作り替えが要る）。いっしょに見るリンク・YouTube のコメント・AI の枠の 3 つが、人数に比例して無料枠を使う作りのまま。毎日配信する人が 1 人いるだけで、月の Redis の帯域（データの通信量）と YouTube の 1 日の枠がほぼ尽きる計算になる（2 章）
- 観点の点
  - **作り切れるか: 4**。一番大事な体験（お題 → 3×3 → 広げる → NOW）は動いていて、残りは磨きと守り。コードの見通しは 1 人＋AI でも保てる（入口表・テスト 41 本・純粋な計算の分離）
  - **続けられるか（人が増えたとき）: 3**。直す所ははっきりしていて、どれも数日で直せる。ただ YouTube だけは、Google の増枠の審査（外の都合）を通らないと上限が残る

## 3. 強み 3・弱み 3

### 強み
1. **枠を節約する作りが最初から入っている**。1 回で 12 語（予備 4）を頼む、書き出しの答えを 30 分使い回す（`src/lib/gemini-guard.ts:17`、`src/app/api/gemini/route.ts:103-109`）、図鑑に十分あれば 4 回に 3 回は AI を呼ばない（`src/lib/gemini.ts:15, 82`）、混んだモデルは 2 分後回し、自動育成はその日の枠の余りだけを使い、上限に当たったら止める（`src/app/api/knowledge/grow/route.ts:12-13, 77-79`）、Redis への記録は 1 回 1 命令にまとめてある（`src/lib/knowledge-server.ts:56-74`）。Twitch は匿名でブラウザから読むので枠が無い
2. **どこが落ちても止まらない**。キーが無い・AI が失敗・回数制限・Redis が読めない、のどれでもオフライン生成に落ちて画面は動き続ける（`route.ts:94-125, 169-176`、`knowledge-server.ts:206-210`）。「キー無しでも動く」【持】が仕組みとして守られている
3. **1 人＋AI でも見通せるコード**。`AGENTS.md` の入口表で触るファイルがすぐ分かる。純粋な計算を分けてテストしている（`topic-knowledge.ts`・`label-quality.ts`・`knowledge-grow.ts`、テスト 41 本）。800 行で分ける決まりがあり、`task.md` も手入れされている

### 弱み（直し方は 5 章）
1. **見る人の数に比例して Redis と関数の呼び出しが増える**（いっしょに見るの 2.5 秒おき・キャッシュ無し・毎回読んでから書く）。しかも全データが 1 つの無料の Redis にあり、1 か所が尽きると全部止まる
2. **全体の使用量を誰も知らない**。守りはサーバー 1 台ごとのメモリと IP だけ（`gemini-guard.ts:3-7`、`src/lib/rate-limit.ts:1-5`）。利用の計測も無い（`package.json` に analytics なし）。Gemini と YouTube は推しログの管理画面で見ているが（`docs/setup.md:76-78`）、Redis と Vercel は見ていない
3. **図鑑を「増やす」のは自動、「減らす」のは手作業**。隠す表はコードに書いてデプロイする方式で 563 行・26KB に育ち、しかもブラウザにも配られている（`src/lib/knowledge-client.ts:18` が `topic-archive` を読む）。棚卸しのたびに全員の読み込みが重くなる

## 5. 必ず変えること（この順で）

### 0. 先に 5 分で確かめる: Vercel のプラン
- Hobby なら、広告タグを Vercel の本番から外し（`src/lib/ads.ts:31, 36` の既定の ID をやめ、環境変数があるときだけ出す）、代わりに応援の導線（本人のメンバーシップへのリンク）を足す。寄付・応援は Vercel でも商用に当たらない。今のアクセスなら広告の売上はほぼゼロ（`market.md` 6 章の目安で月 1 万訪問でも約 4,000 円）なので失うものが小さい。`core.md` ②「ツールは無料公開＋任意の応援、課金は自分のメンバーシップに寄せたい」とも合う
- 広告を続けたいなら Pro（月 $20）か、Cloudflare への引っ越し（L）。【本人の判断】おすすめは「外して応援リンク」

### 1. いっしょに見るの読み書きを軽くする（一番先に尽きる所）
- 読む側（`src/components/watch-view.tsx:131`）: 盤面が変わらない間は 2.5 秒 → 5 秒 → 10 秒と間隔を延ばし、変わったら 2.5 秒に戻す
- 返事（`src/app/api/share/[id]/route.ts`）: `Cache-Control: public, s-maxage=2, stale-while-revalidate=5` を付ける。Vercel の配信網に 2 秒だけ答えを置き、同じ時刻に見ている大勢には Redis を読まずに返す（視聴者が 100 人でも Redis はほぼ 2 秒に 1 回）
- 変わったかだけを先に見る: 書くときに更新時刻だけの小さなキー（`ts:share:u:{id}`）も一緒に書き、読む側は `?v=前の更新時刻` を付ける。同じなら盤面を読まずに「変化なし」とだけ返す → 帯域が 9 割以上減る【推測】
- 書く側（`src/lib/live-store.ts:241, 273-274`）: 持ち主の印を別の小さなキーに分け、「印が合えば書く」を 1 回の命令にする（毎回の盤面まるごとの読み出しが消え、コマンドも帯域も半分）。ハートだけの変化は 5 秒に 1 回にまとめる（`src/hooks/use-watch-share.ts:131` の 2,500 を、変化の種類で分ける）
- 確かめ方: 9 章の 30 分の試しで、Upstash の帯域の増え方が 1/5 以下になること

### 2. AI の枠を全体で数え、尽きる前に図鑑へ寄せる
- `src/app/api/gemini/route.ts:111` の前で、Redis の `INCR ai:{太平洋時間の日付}`（AI を呼ぶ 1 回につき 1 命令）。日々の本当の使用量がこれで初めて分かる
- 1 日の目安（AI Studio で見た RPD の 7 割）を超えたら「節約モード」: 返事の最後の行に `budget: "low"` を付け、`src/lib/gemini.ts:15` の `RECALL_AI_RATE` を 0.25 → 0.05、図鑑から即答する条件（`:82` の 12 語）を 8 語に下げる。自動育成はその日は休む（`grow/route.ts` の先頭で同じ数を見る）
- 入口: 自分のキーでない呼び出しは、ブラウザが付ける `Sec-Fetch-Site: same-origin` か自分のドメインの `Origin` があるときだけ受ける。図鑑への記録（`route.ts:161`）も同じ条件のときだけ。外から直に呼んで図鑑に変な語を入れる穴（`task.md:49`）もこれで細くなる
- 効き目: 枠が尽きる前に「質の良い図鑑の語」に寄せて落ちるので、全員が汎用の切り口に落ちる事態を避けられる

### 3. YouTube の枠
- **増枠の申請を今日出す**（YouTube API Services の監査と増枠の申請。無料。プライバシーポリシーはある）。返事に数週間かかるので、他の作業より先に出す【推測: 期間】
- 読む間隔の自動調整（`src/components/live-chat-dock.tsx:282`）: 直近 2 分に番号（`1E`）や「お題:」のコメントが無ければ 20 秒おき、届いたら 8 秒に戻す。静かな時間が半分なら消費は約 3 割減る（1 日 4.4 時間 → 約 6 時間）
- 残りが少ない日は、配信 URL を貼った時点で「今日は YouTube のコメントの読み取りが混んでいます。Twitch とテストコメントは使えます」と出す。始めた配信が途中で止まるより、始める前に知るほうが信頼を失わない。数は Redis の `INCRBY yt:{日付} 5` をサーバー 1 台ごとに 1 分ぶんまとめて送る（1 時間 60 命令）
- 「ホームでもコメントを読む」（`task.md:25`）は消費を増やすので、増枠が通るまで後に回す
- 調べる価値のある置き換え【未確認】: `liveChatMessages.streamList`（流し続ける読み方。1 回 5 単位は同じだが、1 回の接続で長く読めるなら消費が数十分の一になる）。Vercel の関数でつなぎ続けられるか・REST で使えるかは確かめていない

### 4. 図鑑の入口で締める（棚卸しの手間を人数で減らす）
- 自動育成の昇格（`src/lib/knowledge-grow.ts:63-70`）: 語を次のお題にするのは、その語に票が 3 以上（ハート・NOW・コメントのハートのどれか 1 つ）あり、14 文字以内で「語：意味」でないときだけ。AI が自分の語から勝手に枝を伸ばす流れ（宇宙 → 窒素の鎖の型）を止める。1 時間＋テスト
- **2 人以上が使ったお題だけ一覧に出す**: `RECORD_SCRIPT`・`PICK_SCRIPT`（`src/lib/knowledge-server.ts:60-103`）に「何人が使ったか」を数える Redis の小さな数え方（PFADD。IP をそのまま残さず、ハッシュにして数だけ持つ）を 1 行足し、読み出し（`:106-123`）で人数も返す。図鑑の一覧と人気のお題は「人数 2 以上・同梱・票 6 以上」だけ（`task.md:75` の「一覧のしきい値」の答え）。今ある分は人数の記録が無い＝0 なので「前からあるもの」として出し続け、新しいものだけに効かせる。1 人が 25 分で作った鎖は、本人の AI の節約には使われるが、公開の一覧には出ない
- 隠す表をブラウザから外す: `src/lib/knowledge-client.ts:18` の `withoutArchived` をやめる（サーバーは `knowledge-server.ts:203` と `api/knowledge/route.ts:57` で外しているので、配る前に済んでいる）。同梱データに残っている分はビルドの時点で外す
- 図鑑の読み直し（`knowledge-server.ts:41-42`）: 3 分 → 20 分、500 → 300 お題。そのサーバーで記録した分はすぐ手元に反映しているので（`:259, 302`）、見た目の新しさはほぼ変わらない。帯域は約 1/10

### 5. CI に lint・型・通常ビルドを足す
- `.github/workflows/pages.yml:18-20` は `npm install`・テスト・静的ビルドだけ。`npm ci` → `npm run lint` → `npx next typegen` → `npm run typecheck` → `npm test` → `npm run build` → `bash scripts/build-pages.sh` にする。同じフォルダで AI のセッションが並んで main に積む進め方では、ここが唯一の網
- `:5` の古いブランチ（`cursor/topicstream-nu-app-d395`）の指定を外す。main に入っていない cursor のブランチ 2 本は、どうするか本人に聞く

### 6. 使用量を見える所に集める
- 推しログの使用量の画面（`docs/setup.md:76-78`）に、Upstash の今月のコマンド数・帯域・保存量と、上の `ai:{日付}`・`yt:{日付}` を足す。最低でも Upstash と Vercel の使用量の通知メールを有効にする（通知の有無・段階は【未確認】）。「見張らない」で済むように、超えそうなときだけ届く形にする（`core.md` ①5）

## 7. 最初に出せる最小の形（広める前の「守りの 1 週間」）

いまの機能はそのまま凍結し、5 章の 0〜5 だけを入れた形を「配信者に広めてよい版」とする。

- 入れるもの: Vercel のプランの確認／いっしょに見るの軽量化／AI の全体の回数と節約モード／YouTube の申請と間隔の自動調整と配信前のお知らせ／図鑑の入口の条件／CI／相談窓口の一覧（10 章）
- 入れないもの: 新しい機能すべて（6 章の後回し）
- 出す目安: 9 章の確かめで、いっしょに見る 1 時間あたりの Redis の帯域が 30MB 以下、AI の 1 日の使用が目安の 3 割以下、YouTube の 1 日の最大が 5,000 単位以下。これを満たしてから、配信者向けの告知・クレジット表記のお願いを強める
- この形での余裕【推測】: Redis 帯域は毎日配信する人 5〜10 人分、AI は節約モードで枠の 2〜3 倍の人数、YouTube は増枠が通るまで 1 日 6 時間ほど（Twitch は制限なし）

## 8. より良くするアイデア（芯を残すもの、3 つ）

1. **節約モードを「質の良い語から先に使う」にする**。枠が少ない日に図鑑から出す語を、票がある語・2 回以上出た語に絞る（`src/lib/topic-knowledge.ts` の引き方の重みに、票の無い語を下げる係数を 1 つ足す）。同じブラウザで同じお題に前に出した語は後ろへ回す（localStorage に お題 → 出した語 を 20 件）。枠を守るほど同じ 8 枚が並ぶ、を避ける。質と節約が同じ向きになる
2. **「2 人以上が使ったお題だけ一覧に出す」を、人気のお題とお題ページの候補にも使う**。今の人気のお題は手書きの初期点数のまま（`brief.md` 3 章）。人数で数えると、1 人の連打や鎖では動かず、本当に使われたものだけが上がる。荒らし対策と棚卸しの手間の削減が 1 つの仕組みで済む
3. **月 1 回の「AI の定期点検」を予定で回す**。予定を組んだクラウドの AI が、公開 API で図鑑を読み、怪しい候補（17 文字以上・「の」が 3 つ以上・「語：意味」の誤り・窓口の重複・体の話の断定）と、定点のお題 10 個の出力の変化、使っているモデルの引退予告（`src/lib/constants.ts:25-33` の 4 つ）を 1 枚にまとめ、`src/lib/topic-archive-data.ts` への追記を PR にする。本人は見て押すだけ（15 分）。「長い待ちを見張らない」「全部は自分でしない」（`core.md` ①5）に合う

## 9. 一番安く早く確かめる方法

- **誰が・何分**: 本人が 20 分（または、本人の OK のうえで AI が Vercel のつなぎ込みで読む）
- **見るもの（4 つの数字）**
  1. Vercel → プラン（Hobby か）と Usage（今月の関数の呼び出し・Fast Origin Transfer）
  2. Upstash → 今月のコマンド数・帯域・保存量
  3. AI Studio → Rate limit（`gemini-3.5-flash-lite` と予備 3 つの 1 日の上限と、28 日の最大）
  4. Google Cloud → YouTube Data API → Quotas（1 日の最大の使用量）
- **30 分の試し**: 配信はせず、いっしょに見るリンクを OBS かブラウザのタブで 30 分開いたまま、カードを数回広げる。Upstash の帯域とコマンドの増え方を見て 1 時間あたりに直す（計算では 30 分で 20〜60MB・2,000〜4,000 回【推測】）
- **判断**: 「無料の上限 ÷ 今の 1 日（1 か月）の最大」が 10 倍に満たないものから直す。Hobby で広告タグがあるなら、その日のうちに 5 章 0 を決める
- **やめる目安**: 30 分の試しで帯域 5MB 未満・1,000 回未満なら、5 章 1 は後ろに回してよい（見積もりが外れている）。AI の 1 日の上限が 1 万回以上と分かったら、5 章 2 は入口の確認だけにしてよい

## 10. 安全（観点の外だが、その場で指摘）

- **死・自傷の話題で相談窓口が出ない**。お悩み相談の注意書きは「専門の窓口にも話してください」だけで、具体的な窓口はコードに無い（`brief.md` 15 章、`src/lib/modes.ts:134`）。`core.md` ③は、死・自傷の話題では相談窓口の一覧（哲マロの `shared/crisis.ts`）を必ず添えるとしている。哲マロのその一覧をそのまま持ってきて、お題やカードに「死にたい・消えたい・自殺・自傷」などが入ったら、マップの上に一覧を出す（S、半日）。重い悩みを公開のまま通す【持】（`task.md:12`）は変えない
- **体の話の断定を止める一文が無い**。安全の一文は個人・差別・個人情報だけ（`src/lib/public-text.ts:73`）。「体や病気の話は断定せず、診断や治療をすすめる切り口にしない」を足す（S、10 分）。例 13（低血圧の鎖）の型を防ぐ
- 視聴者の年齢層は分からないが、開発者フッターに性癖カルテが並ぶ（`src/components/related-services.ts:6`）。配信者が子ども向けの枠で使うときに気にしないかは本人の判断【未確認】
